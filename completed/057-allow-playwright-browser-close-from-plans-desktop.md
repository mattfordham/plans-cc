The answer to "should we add Sentry / Better Stack tools?" is a reasoned **no**, revisited only if a future skill actually introduces an error/log-reading workflow.

So this task settles on **five** tool additions across the two browser-driving skills and des-build's Figma list: `browser_close`, `browser_click`, `browser_type`, `browser_console_messages` (Playwright, both skills), plus `get_variable_defs` and `create_session` (Figma, des-build only).

## Why
Improves reliability by stopping plan execution from being interrupted by spurious tool-call denials. During the visual-comparison stage, the model emits benign MCP calls as routine setup, interaction, and teardown — all legitimate, non-destructive calls the *written* verify workflow genuinely needs, yet missing from the driving skill's `allowed-tools`, so the harness denies them and warns that "the plan may be built on incomplete information." The denied/at-risk calls fall into one benign pattern:

- **Browser teardown:** `mcp__playwright__browser_close` — closing the Playwright browser after measuring.
- **Variant-state setup the workflow names:** `mcp__playwright__browser_click` and `mcp__playwright__browser_type` — Step 8a item 3 instructs the model to "click toggles, open menus, type into search" to put the page into each Figma variant state before measuring it.
- **Render-failure diagnosis:** `mcp__playwright__browser_console_messages` — when the review page fails to render (a FAILED stage in both Step 8a and Step 11.5a), reading console errors is the benign way to explain why.
- **Figma reads confined to des-build:** `mcp__figma-dev-mode-mcp-server__get_variable_defs` to read token/variable values against the design system, and `mcp__plugin_figma_figma__create_session` as the Figma plugin server's mandatory per-file prerequisite.

Each should simply be allowed so a `des-build` verify pass runs clean. This pass also deliberately scopes the fix: it adds only tools the written workflow names or clearly needs, and it explicitly does **not** add Sentry, Better Stack, or a broad pre-emptive set of browser/Figma tools — none of which any skill's workflow references today (a repo-wide grep returns zero Sentry/Better Stack matches), so granting them would be over-reach with no workflow behind it.
