## What
Task #029 capped the `.plans/HISTORY.md` Summary cell (one sentence, `<verb-phrase> — <what changed>`, plus a ` → completed/NNN-slug.md` pointer, ≤250 chars) but deliberately stopped at *documenting* a backfill procedure in `CLAUDE.md`. Existing projects therefore still carry fat pre-cap rows (observed in `~/work/multi-repo-app`: ~900K across 556 lines, 552 fat rows, worst row 9,020 chars) with no command to fix them.

Add an opt-in backfill mode to `/plan-cleanup` that rewrites pre-cap rows in place.

**Why `/plan-cleanup` and not `/plan-audit`:** cleanup's stated purpose is already "rebuild state from ground truth" — it reconciles PROGRESS.md against reality, reaps orphaned state files, and cross-checks `git worktree list` against `.worktrees/`. A fat HISTORY.md is the same species of problem: on-disk data drifted from a documented contract. `/plan-audit` is the wrong axis — it is per-task (`<id>`), refuses `completed` tasks outright, and verifies a task's *implementation* coverage, not repo-wide data hygiene.

**Detect vs. perform split (load-bearing).** Every other cleanup operation is mechanical (delete an orphan, prune a worktree, recount stats). Backfill is not: regenerating a summary means reading `completed/NNN-slug.md` and writing a new sentence — an LLM judgment call per row, ~552 of them. So it must NOT run silently in the default sweep. The default sweep only **detects and reports** drift (e.g. `312 HISTORY.md rows exceed the 250-char cap; run /plan-cleanup history to backfill`); the rewrite happens only under an explicit `/plan-cleanup history` invocation. This mirrors an existing repo pattern: `des-build` flags global-CSS drift and points at `/des-sync` rather than fixing it itself.

## Why
Adds value by giving existing projects a safe, repeatable way to adopt the HISTORY.md cap that #029 defined but deliberately left unexecuted. #029 shipped the contract (one-sentence shape + ` → completed/NNN-slug.md` pointer, ≤250 chars) and wrote the backfill procedure into `CLAUDE.md`, but that procedure is prose a human has to hand-drive — so every pre-cap project still carries fat rows (multi-repo-app: ~900K/556 lines, 552 fat rows, worst row 9,020 chars) with no command to fix them. This turns the documented procedure into an invocable, resumable, non-destructive mode, and makes the *drift itself* discoverable by reporting it from the default sweep.

## How Summary
Add a third mode to `/plan-cleanup` — `history` — alongside its existing full/focused modes, mirroring `plan-retrospect`'s first-token mode-keyword idiom (`argument-hint: "[id | history]"`). The work splits along a **detect vs. perform** line: a new detect-only step in the default sweep counts rows whose Summary cell exceeds the cap and FLAGS them pointing at `/plan-cleanup history` (never rewriting — mirroring des-build's established "FLAG it and tell the user to run `/des-sync`… NEVER syncs itself" discipline), while the rewrite happens only under the explicit `history` invocation. The rewrite pass previews its first 3 rewrites for approval, then proceeds in ID order with prose progress reporting; it is naturally idempotent (already-capped rows are skipped) and therefore safely re-runnable across context windows. Rows whose `completed/NNN-slug.md` is missing are skipped and reported rather than guessed at. All changes are prose in declarative SKILL.md files — no runtime code, consistent with #028/#029 and with the fact that nothing in `lib/`/`bin/`/`test/` reads HISTORY.md.
