# Branch mode: tracked plans on a dedicated `plans` branch

Shared spec for tasks #040–#042. The source design came from a plans-desktop session (2026-10-05).
Open questions were resolved interactively, and the claims were checked against the code on the same day.

## Goal

Keep `.plans/` in git so plans can be read, captured, and executed from remote sessions
(claude.ai/code, another machine). Plan state must not depend on which code branch is
checked out, and worktree execution and the desktop app must keep working.

## Design

- Plan state lives on an **orphan branch** (default `plans`) with no shared history with code branches.
- That branch is checked out as a **permanent git worktree at `<root>/.plans`**.
- `.plans` stays in the code branches' `.gitignore` exactly as today (slashless form).
- Consequences: `.plans/` is still one physical directory that doesn't depend on the code checkout.
  The plan-execute 7e and multi-repo step 4 symlinks still work, because `git worktree add` never
  populates an ignored path. The desktop app keeps reading `<root>/.plans` unchanged. Code history
  stays free of plan churn.

### Mode detection (single rule)

`.plans` is in branch mode when `git -C .plans rev-parse --show-toplevel` resolves to the
realpath of `.plans`, and that differs from the project root's toplevel. Otherwise the existing
local/inline logic applies unchanged.

### Config (read defensively, like `models`; absent ⇒ defaults; never seeded for non-branch projects)

```json
"sync": { "remote": "origin", "branch": "plans", "auto_push": true }
```

## Decisions (resolved 2026-10-05)

| # | Question | Decision |
|---|----------|----------|
| 1 | plans-cc availability in remote sessions | SessionStart hook runs `npx -y plans-cc`, then `plans-git.js bootstrap` |
| 2 | Multi-repo parent roots (not a git repo) | Unsupported in v1. `plan-init` refuses branch mode with a clear message |
| 3 | `.plans/state/` | **Tracked**, so remote sessions can resume mid-execution (files are per task, so conflicts are rare) |
| 4 | Push timing | Commit synchronously, push async/best-effort. **ID-minting commits push synchronously** |
| 5 | Branch name | Configurable via `sync.branch`, default `plans`. `bootstrap` accepts `--branch` (it can't read config.json before fetching) |
| 6 | plan-init default | Branch mode is **offered**. "Ignore" stays recommended |
| 7 | Concurrent commits into the shared `.plans` worktree | `git add -A`, wrapped in a `mkdir`-based lock (`.plans/.git-lock`, ignored) with short retries. Sync uses `pull --rebase --autostash` |
| 8 | `PROGRESS.md` | **Tracked**, with `merge=ours` in `.gitattributes`. Rebuilt after any sync that changed task files |

### Implementation caveats surfaced during the decisions

- `ours` is **not** a built-in git merge driver (only text/binary/union are). Every clone needs
  `git -C .plans config merge.ours.driver true`, so `plan-init` (create/migrate/join) and
  `bootstrap` must set it. During a rebase, "ours" is the upstream side. That's fine for a file we
  always regenerate.
- Today PROGRESS.md is regenerated by the skills themselves (the model), not by Node. For `sync` to
  rebuild it, it needs a Node renderer. `lib/parse-tasks.js` already parses task status and is the
  natural base. If that renderer is deferred, `sync` must at least leave PROGRESS.md correct-or-stale,
  never conflicted.
- **`git_commits` vs branch mode.** This repo's own config has `git_commits: false`. In branch mode,
  commits *are* the sync mechanism, so `git_commits: false` would silently disable sync.
  Recommendation: in branch mode, `plan-init` writes `git_commits: true`, and the helper warns once
  if it finds `false` in branch mode. It never flips the value silently.
- `.gitattributes` on the plans branch: `HISTORY.md merge=union`, `PROGRESS.md merge=ours`.
  `.gitignore` on the plans branch: `.DS_Store`, `.git-lock`.

## Verified against code (2026-10-05)

- **Commit block:** exists in 25 skills (20 under the literal heading "Commit .plans/ changes"). Every
  copy has the shape `git check-ignore -q .plans` → exit 0 → *skip silently*. In branch mode `.plans`
  IS ignored by the outer repo, so nothing would ever commit. The doc's central claim is confirmed.
- **Worktree symlinks:** `plan-execute` step 7e.5 (`ln -s [project-root]/.plans [worktree-path]/.plans`,
  around line 465), multi-repo step 4 (`ln -s ../../.plans`, around line 496), and `plan-spawn` around
  line 166. All symlink to the root path, so they work unchanged when that path is a worktree.
- **`plan-cleanup` 7.5:** detects tracking with `git ls-files | grep -E '^\.plans($|/)'` on the
  *outer* repo. A nested worktree of an ignored path is not in the outer index, so **branch mode
  will not be false-flagged**. No change is needed beyond documenting this. Keep the trailing-slash
  warning.
- **`plan-cleanup` worktree reconciler:** filters `git worktree list --porcelain` to paths under
  `.worktrees/`, so the `.plans` worktree is naturally excluded from reaping. Add an explicit guard
  anyway, plus a comment. The unconditional `git worktree prune` is harmless, because a present
  `.plans` worktree is never stale.
- **`plan-complete`:** the merge dispatch looks up `branch refs/heads/[target-branch]` in
  `git worktree list`. The plans branch is never a target, so there's no interaction.
- **`plan-init` step 7:** currently offers two options (Ignore, Check in). Branch mode becomes option 3.
- **ID minting:** 8 skills read `next_id` / `idea_next_id`: capture, brainstorm, import, init,
  mine, pick, spawn, unpack. The existing "reconstruct next_id from highest id" logic scans only
  `pending/` and `completed/`. **It omits `backlog/`**, which the renumber path must include
  (pre-existing gap).
- **`lib/find-root.js`** keys on `fs.statSync(<dir>/.plans/config.json).isFile()`, so it resolves
  through a worktree directory. Add a test.
- **Tests:** `test/` has `find-root.test.js` and `registry.test.js`. `npm test` = `node --test`.
- **Helper install path precedent:** skills call `node ~/.claude/plans-cc/plan-touch.js` best-effort.
  `plans-git.js` should install alongside it via `bin/install.js`.
- **git:** local is 2.50.1, so `git worktree add --orphan` (≥2.42) is available. Keep the
  `commit-tree` empty-tree fallback for older git.
- **plan-cleanup / doc mismatch:** the doc names `plan-expand`. The skill is `plan-unpack`.

## Acceptance criteria (whole feature)

- With branch mode on, capturing while `main`'s checkout is on any code branch commits the task to
  `plans` and leaves the code branch untouched.
- An execution worktree's status/progress writes land in `<root>/.plans` and are committed on `plans`.
- A plan captured in a remote session appears locally after `sync`, and vice versa.
- Two machines capturing concurrently never end with duplicate ids.
- Projects in local or inline mode behave byte-for-byte as before.
- `plan-cleanup` reports branch mode as healthy and never offers to untrack or reap it.
